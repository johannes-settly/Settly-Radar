# Risks and mitigations

| Risk (from workshop) | Mitigation in Radar |
|---|---|
| Building on a tool that gets replaced (CRM/outreach decision ~end Nov) | Stay tool-agnostic until decided: analysis, data model, scoring logic first; integrations after |
| Wrong timing / missed signals | Inventory signal types; measure which historically produced meetings; add Settly-specific timing signals from own conversations |
| Limited or no ROI | Every initiative gets a metric (meetings/week, SQLs, signal accuracy) and expected impact before work starts |
| Optimising efficiency, forgetting top of funnel | Primary metric is new qualified meetings, not hours saved |
| No agreed TAM/SAM | First deliverable: documented, sourced TAM→SAM estimate signed off by Marieke |
| Focusing on the wrong bottleneck | Validate with data (where does the funnel actually leak vs targets?) before committing to a build |
| Generic tool data under-covers niche ICP | Quantify coverage gap; enrich with NL-specific sources (IND, 30% ruling, KvK) and own history |
| GDPR / data provenance | Contact data only via certified tools; no personal data in repo |
| Dirty historical data | Start from customers and recent deals; agree a one-time cleanup scope |
